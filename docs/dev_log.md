## Development Log: Microfinance Loan Tracker

| # | Date | Focus | What I did | Outcome / decision |
|---|---|---|---|---|
| 1 | 2026-07-29 | Project scaffold | Worked through the PRG2104 project brief and mapped its requirements onto a concrete structure before writing any UI code. Settled on an immutable domain model (`Borrower`, and `Loan` split into `MicroLoan`/`GroupLoan`), a generic `Repository[T]` for in-memory storage, and CSV files for persistence, with the four screens (Register Borrower, Disburse Loan, Repayments, Dashboard) as separate objects under `ui/`. | Scaffolding only at this stage, nothing had been compiled or tested yet, so none of it could be treated as finished. |
| 2 | 2026-07-30 | Getting it to compile | Ran `sbt run` for the first time; it produced eleven errors across four files. Most traced back to `scalafx.Includes` not being imported, which meant `handle {...}` and `stylesheets += ...` weren't resolving, plus one ambiguous `ComboBox` cellFactory overload and a redundant `ObservableBuffer.from(...)` wrapper that didn't type-check. Fixed each one and re-ran, which turned up a second, smaller round of issues (an unreachable pattern match in `MainApp`, some `-Wunused` warnings, and a label that was built but never actually added to its layout, so it silently never rendered). | Cleared all of it on the second pass. |
| 3 | 2026-08-01 | First working build | Got the application running end to end for the first time. Registered a test borrower to confirm the CSV round-trip worked, and noticed two rough edges: the registered-borrower list was truncating longer names, and income was displaying with Scala's default `Double` formatting instead of two decimal places. Widened the list and the main window, and switched income display to an `f"...%.2f"` interpolator. | Also went back through the remaining compiler warnings to confirm which imports were genuinely unused versus still load-bearing. |
| 4 | 2026-08-02 | Button and layout consistency pass | Noticed the action buttons across screens weren't visually consistent, tried a custom `.primary-button` CSS class first, then reverted it in favour of just using JavaFX's native `defaultButton = true` styling on all of them. Separately, found that the Register Borrower screen wasn't stretching to fill the window the way the other three screens did; traced it to the outer containers and list view not being told to grow. | Fixed by setting `maxWidth` and using `HBox`/`VBox` grow priorities so the layout fills the available space properly. |
| 5 | 2026-08-03 | Iterating on the Repayments screen colour scheme | Tried giving "Mark Repaid" a distinct light red style, separate from the light blue used everywhere else, and spent a few rounds adjusting the exact shade so it read as red rather than maroon, lightening it to match the visual weight of the native blue buttons. Also matched the Dashboard's statistic figures to the same blue-grey used in the Repayments table headers. | After sitting with the red button for a while, decided the extra colour didn't actually add clarity and reverted it back to the same native light blue as the other three buttons. |
| 6 | 2026-08-04 | Small bug triage | Investigated a report that the Group size field couldn't be typed into; confirmed it was working as designed (it's disabled until "Group" is selected as the loan type, since Micro loans don't need one) rather than an actual defect. While checking it, also noticed the focused-field border colour didn't match the app's blue accent. | Adjusted the token used for `:focused` styling to bring it in line with the rest of the app. |
| 7 | 2026-08-06 | Borrower field, typeable and sorted | Reworked the Borrower field on the Disburse Loan screen from a fixed-selection dropdown into an editable, filterable one, sorted ascending by borrower id, so it can be typed into as well as selected. Took more than one pass: the first version had three compile errors from mixing raw JavaFX types with ScalaFX's wrappers, fixed with a missing `scalafx.Includes` import plus a small buffer-copying fix. | Functionally solid after that, but visually it stood out from the rest of the form, which set up the next session's styling work. |
| 8 | 2026-08-07 | Matching the Borrower field's styling properly | Spent the most time this session on getting the Borrower box to actually look like the rest of the form. Learned that an editable `ComboBox` in JavaFX isn't one styled control, it's an inner text field and arrow-button glued together, which don't automatically inherit the app's usual styling. Went through several iterations on height, border weight, and width, including one mistake where a CSS change made the box's background disappear entirely instead of unifying it, since JavaFX doesn't paint a background on an editable ComboBox's outer control by default. | Settled on wrapping the control in a plain container using the exact same style class as the Principal field, rather than trying to recreate its look separately, which finally gave a proper pixel match. Repackaged and did a final pass over all four screens before treating the build as submission-ready. |
